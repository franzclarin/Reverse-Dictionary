Add sound effects to make the search experience more immersive

P3 · polish ✓ Done · 2026-08-26
Touches: context/SoundContext.tsx (new), app/layout.tsx, components/Navbar.tsx, components/SearchInput.tsx, components/SearchResults.tsx, components/WordShareButtons.tsx Risk: low — additive, muted by default preference is respected, no new dependency Est: ~1 hr

User request: make the reverse dictionary feel more immersive with sound. The app has no public/ directory and no audio-file assets anywhere, and the project already avoids adding dependencies where the platform can do the job — so effects are synthesized at call time with the Web Audio API rather than shipping .mp3/.wav files.

Size — S
1 new context, 4 call sites wired
No new npm dependency. No public/ assets. All five effects are oscillator/noise-burst functions in one file.
Impact — low-risk polish
Search flow + word-page copy button
Doesn't touch retrieval, the API, or the data model. Purely a client-side UX layer, off by a persisted toggle if a user doesn't want it.

Task

  1. Add context/SoundContext.tsx: a SoundProvider exposing { enabled, toggle, play(name) }. Effects are synthesized with AudioContext oscillators and filtered white-noise bursts — no audio files. Preference persists to localStorage under rd-sound-enabled (default on); the AudioContext itself is a module-level singleton (not React state) since browsers cap how many can exist per page and it needs to survive remounts.
  2. Theme the five effects to the site's existing paper/typewriter motif (serif ¶ mark, rd-stamp-in animation, DM Mono) rather than generic UI beeps:
    • key — short bandpass-filtered noise burst, pitch-varied across 4 variants, on every character typed or deleted in the search box.
    • return — a bell-like sine ding on search submit (typewriter carriage return).
    • stamp — a pitch-dropping low thud plus a tight noise transient when results land (a rubber stamp hitting paper).
    • error — a soft descending two-note tone for request errors or zero matches — deliberately not alarm-like.
    • click — a small neutral click for secondary actions: "Load more entries", copying the share link, the X/Twitter share button, and turning sound back on from the mute toggle.
  3. Wrap app/layout.tsx's tree in SoundProvider (outside LoadingProvider, since the two are independent).
  4. Add a mute/unmute icon button to components/Navbar.tsx, right-aligned, aria-pressed + aria-label reflecting state, matching the nav's existing focus-ring and hover treatment.
  5. Wire call sites: SearchInput (key clicks on onKeyDown, ding on submit), SearchResults (stamp on results found, soft error tone on failure or zero matches, click on "Load more"), WordShareButtons (click on copy-link and on the X share button).

Prerequisite knowledge

Browsers start a freshly-constructed AudioContext in "suspended" state and only let it actually produce sound after a user gesture; calling resume() outside a gesture is a harmless no-op, not an error. That means the stamp/error sounds on a search page loaded directly from a URL (no prior gesture in that tab) will silently not sound until the user's first keystroke or click resumes the context — expected platform behavior, not a bug to route around.

Learnings

✓

Keep play out of the fetch effect's dependency array. SearchResults' result-fetching useEffect calls play() as a side effect but must not depend on it — play's identity changes when enabled toggles, and including it would re-run the fetch every time the user muted/unmuted mid-search. Fixed with a playRef updated on every render instead, the same pattern the file already uses for requestIdRef.

✓

A hard minimum-gap floor per sound name (35ms for key, 60–200ms for the rest) stops key-repeat or a paste from turning into a buzz of overlapping bursts — cheaper and simpler than a debounce/queue.

Acceptance criteria

  • Typing in the search box produces a per-character click; submitting produces a distinct ding
  • A successful search plays a stamp sound; an error or zero-result search plays a soft error tone, not the stamp
  • "Load more entries" and the word-page share/copy buttons play a neutral click
  • A nav toggle mutes/unmutes all effects and the choice persists across reloads via localStorage
  • npx tsc --noEmit and npm run lint both pass clean
  • No new npm dependency and no new files under public/
