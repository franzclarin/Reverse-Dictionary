Add a favicon — the site currently ships with none at all

P3 · polish ✓ Done · 2026-08-26
Touches: app/icon.svg (new, App Router auto-detected) Risk: none Est: ~15 min

Verified before starting: no public/ directory exists in the repo, nothing under app/ matches favicon/icon, and app/layout.tsx's metadata export has no icons field. The browser tab currently shows no icon at all — not even Next's own default.

Size — XS
1 new file, zero code changes
Next.js 14 App Router auto-detects app/icon.* by file convention — dropping the file in is the entire implementation, no layout.tsx metadata wiring required.
Impact — low, cosmetic
Every browser tab, bookmark, and history entry
Doesn't touch search or retrieval. Purely finishes the editorial redesign — the nav already uses a serif "¶" pilcrow mark as its logo glyph, so the favicon reuses that instead of inventing new iconography.

Task

  1. Add app/icon.svg: a pilcrow (¶) glyph on the site's accent color, matching components/Navbar.tsx's logo mark so the tab icon and the in-page logo read as the same brand.
  2. No layout.tsx change needed — Next 14 App Router picks up app/icon.svg automatically and serves it at /icon.svg with the correct <link rel="icon"> tag injected into every page's <head>.
  3. Verify in a running dev server that the tab shows the icon and /icon.svg resolves.

Prerequisite knowledge

Next.js's file-convention icons (app/icon.{ico,jpg,jpeg,png,svg}, optionally app/apple-icon.png for iOS home-screen use) are resolved at the segment level and merged into generateMetadata's output automatically. This is the only icon mechanism this app needs — there's no multi-brand or per-locale icon requirement that would call for the alternative public/favicon.ico + manual metadata.icons approach.

Learnings

✓

Zero-config was actually zero-config. No public/ directory needed to exist first, and no metadata object needed editing — the App Router's file-convention detection handled everything once app/icon.svg was in place.

Acceptance criteria

  • app/icon.svg exists and matches the nav's pilcrow mark
  • Browser tab shows the icon when running npm run dev
  • /icon.svg resolves with a 200 and correct content type
