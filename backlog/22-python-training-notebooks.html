A Python surface for training and experiments

✓ Done P2 · tooling
In plain terms

Today — this repo could measure models beautifully and could not build one at all. There was no training code in it: no Python, no notebooks, nothing. The model that powers the whole app was trained once, in a Colab notebook that was never checked in, and the copy of it that used to sit in the project folder is gone.

Done — added training/: a Python library and five notebooks that can fine-tune either model, score the result, and hand it back to the existing harness. Fine-tuning now runs on the laptop.

Why it matters — every remaining idea in this backlog is "train something". Until now that meant leaving the repo, losing the eval harness, and coming back with a number nobody could reproduce.

Status: done 2026-08-30 — parity gate passes 9/9, round-trip is 287/287 identical Unblocks: RD-09, RD-12/RD-13, RD-14, RD-15 Touches: training/ only — no application code, no runtime dependency, no change to the serving path Risk carried: a second scoring implementation, deliberately accepted and pinned

The evaluation half of this project is careful to a fault. The training half did not exist. This closes that gap without spending the first half to buy the second.

What was actually missing

A survey of the repo before this ticket: zero .py files, zero notebooks, no torch, no sentence-transformers. reverse_dict_model.zip — which CLAUDE.md described as sitting at the repo root and holding model.safetensors — was not on disk.

The recovery turned out to be free. The Hugging Face repo franzclarin/ReverseDictionary ships model.safetensors alongside the full sentence-transformers layout (1_Pooling/config.json, modules.json, sentence_bert_config.json), so SentenceTransformer("franzclarin/ReverseDictionary") loads it as a trainable PyTorch model with the correct Transformer → Pooling → Normalize stack. The lost zip does not matter.

The decision that shaped it

METHODS.md is explicit that a second embedding path "would make every number fiction", and the harness is built around that: scripts/lib/retrieval.ts mirrors the route, and eval.ts imports embed from lib/embedder.ts rather than reimplementing it.

A self-contained Python loop was chosen anyway, for iteration speed — and then pinned, which is what this repo does with every other second implementation:

existing precedentwhat it pins
npm run verify-vizthe browser's reimplemented WordPiece tokenizer against the real AutoTokenizer, 415/415
rd17_controlhad to reproduce RD-16's full_gloss_ft to the digit before either arm could be read

rdlib.parity is the same move. It re-derives the published figures from the committed runs, re-derives the paired McNemar tests, recomputes echo from scratch rather than trusting the stored field, and compares the PyTorch encoder against the ONNX artifact that actually serves /api/lookup. It raises on failure.

The rule this establishes

Python numbers are for iteration. Any number that would change a decision gets confirmed through npx tsx scripts/eval.ts before it is written down.

The gate proves the two agree on everything checkable. It does not prove that a local exact scan matches the live IVFFlat index — those are different retrieval methods and differ by ~0.3 points by design. A cell scan is the right instrument for "is this representation better" and the wrong one for "what will users get".

What it costs to run an experiment now

RD-16's six cells were an overnight job. A representation experiment is now a coffee break — which matters, because the cheapest lever in this repo is still changing what gets indexed, and that needs no GPU at all.

Prerequisite knowledge

The gate that is not optional

evalset.assert_disjoint() raises if a training pair uses an eval query or an eval target. It fires on any raw WordNet slice, because the eval targets are ordinary English words drawn from the same dictionary — that is the gate working. The notebook documents the two legitimate responses and requires the choice to be recorded, because the original fine-tune was trained with eval_on_start: False and prediction_loss_only: True: no evaluator, no held-out split, and a recorded 10.9% that describes memorisation and cannot be cited.

Traps that are silent

  • WordNet files are latin1. Reading them as UTF-8 mangles accented headwords and breaks inputsSha256 parity.
  • percentile does not interpolate. metrics.ts floor-indexes; np.percentile interpolates.
  • Mean pooling, no prefix. Correct for the fine-tune, MiniLM and gte. Silently wrong for BGE (CLS pooling) and E5 ("query: " prefix) — those produce plausible vectors that are not what the model was trained to emit.
  • 384 dimensions to ship. GlossEmbedding is halfvec(384) — one of three independent reasons all-mpnet-base-v2 was rejected at +2.8pp.

What was deliberately not ported

rdlib.wiktionary reads the Kaikki dump for training pairs only. It is not a port of scripts/lib/wiktionary.ts, whose FILTER_VERSION = "rd17.2" produced the 575,534 senses currently in GlossEmbedding and whose per-rule kill counts are a committed artifact. A second implementation of that would be a live drift hazard against a production table; a reader that only emits (word, pos, gloss) cannot change what users search.

Learnings

✓

The interop format was already language-neutral, and nobody had noticed. A cell is raw little-endian float32 with a JSON sidecar — np.fromfile reads one and ndarray.tofile writes one. The entire Python↔TypeScript bridge is about forty lines. The expensive-looking part of this ticket was free because of a format decision made for an unrelated reason two tickets earlier.

✓

A second implementation is only dangerous if it is unchecked. METHODS warns against one, and the warning is right — but the repo's own answer everywhere else is a parity check, not abstinence. Pinning the port cost one module and caught nothing, which is the outcome a gate is supposed to have; what it buys is that the next change to metrics.py cannot silently drift.

!

The documentation described an artifact that was not there. CLAUDE.md named reverse_dict_model.zip at the repo root as the source of the original model; it is gone, and had it been the only copy, retraining from the current weights would have been impossible. The Hugging Face repo turned out to hold everything. A gitignored file named in the docs is a claim nobody re-checks — the same failure shape as the stale 512 MB storage ceiling RD-17 corrected.

✓

Fine-tuning this model was never the hard part. A MiniLM is 22M parameters; the full WordNet index encodes in 28 seconds on a laptop. What made retraining expensive was never compute — it was the absence of a way to score the result against everything already measured.

Acceptance criteria

  • Parity gate reproduces every published figure from the committed runs, and raises on failure
  • Paired McNemar tests re-derived and matching the recorded wins/regressions
  • The echo rule recomputed independently and matching the stored field
  • PyTorch and served-ONNX encoders shown to agree within float32 rounding
  • A Python-built cell readable by eval.ts, scoring identically per query
  • Disjointness gate that raises, demonstrated firing on real data
  • No application code, runtime dependency, or serving-path change
