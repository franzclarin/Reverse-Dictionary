Remove orphaned games code left behind by the games-UI removal

P2 · cleanup
Touches: lib/gameTokens.ts, lib/gameUtils.ts, lib/credits.ts Risk: low — verified zero live callers Est: ~1 hr

The five casino-style word games and their API (1ad57f8, "Remove games UI and StreamlinedSongs link") were removed from the app, but the backend plumbing built for them wasn't. This was verified directly this session — not inferred from a commit message — by grepping every caller of each function.

Size — S
2 file deletions + 3 function removals
Deletion, not modification, of code with zero verified callers. The only real work is confirming the two live callers (/api/credits, /api/word/[word]/save) still pass afterward.
Impact — low
Zero user-facing change
Pure code-health: smaller surface area, one less orphaned Upstash rate limiter to reason about, one fewer stale env var to explain to a new contributor. Nothing a user or the retrieval numbers will ever notice.

Task

  1. Delete lib/gameTokens.ts in full — zero importers anywhere in app/, lib/, components/, or scripts/.
  2. Delete lib/gameUtils.ts in full — same, zero importers. Note it holds its own second Upstash rate limiter (getGameRatelimiter), entirely separate from and unrelated to the one in app/api/lookup/route.ts.
  3. In lib/credits.ts, remove settleGame, awardDailyLookup, and awardWordShare — each individually verified to have no callers. Keep getOrCreateUser, getCredits, and awardCredits (used by /api/credits) and awardWordSave (used by /api/word/[word]/save).
  4. Remove the now-unused GAME_TOKEN_SECRET env var reference from documentation (it was only ever read inside lib/gameTokens.ts).
  5. Leave the GameRound Prisma model and User.streak/User.gameHistory fields alone for now — see Learnings for why this is a separate, riskier decision than deleting the TypeScript code above.

Why GameRound the model is scoped out

lib/credits.ts's settleGame writes to prisma.gameRound, and scripts/inspect-eval-sources.ts also references it — so unlike the two fully-orphaned files, the Prisma model has at least one other touchpoint to check before removal. Dropping a model means a migration (irreversible without a restore), where deleting unused TypeScript functions is a same-day revert. Different risk tier; don't bundle them into one PR.

Learnings

✓

"Removed" in a commit message doesn't mean removed. 1ad57f8's title says the games UI was removed; the backend half of that feature — three functions, two full library files, one env var, one secondary rate limiter — was left in place. Grep the actual call graph before trusting a removal commit's scope, even your own.

✓

The credits system itself is still live and load-bearing — this isn't "delete the whole credits feature." Users still earn credits for saving words and see a leaderboard; only the games-specific award paths are dead.

Acceptance criteria

  • lib/gameTokens.ts, lib/gameUtils.ts deleted
  • settleGame, awardDailyLookup, awardWordShare removed from lib/credits.ts
  • npx tsc --noEmit and npm run lint clean afterward
  • /api/credits and /api/word/[word]/save manually re-verified working (they're the two real callers left in the file)
  • GameRound model and its two other references explicitly left alone, noted as future work if ever revisited
